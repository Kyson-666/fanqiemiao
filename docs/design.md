# 番茄喵 Web · 架构与实现说明

> 本项目是 Rust 内核 [`zhongbai2333/Tomato-Novel-Downloader`](https://github.com/zhongbai2333/Tomato-Novel-Downloader)
> 的 **Web 封装**：番茄小说的搜索 / 详情 / 下载由该内核提供，本版补齐七猫小说、榜单与网页界面，
> 并打包为可一键 Docker 部署的单容器服务。
>
> 本文档说明：**① 项目依赖；② 总体架构与关键设计；③ 风险与边界；④ 使用声明。**

---

## 一、项目定位与依赖

本项目**不实现番茄小说的内容抓取**，而是把内核当作本地引擎来编排：

```
┌────────────────────────────────────────────────────────┐
│ 番茄喵 Web（Node 服务 + 原生前端，单容器）                │
│  ├─ 番茄搜索/详情/下载：调用内核 REST（127.0.0.1:18423）  │
│  ├─ 番茄榜单：直抓 https://fanqienovel.com 网页           │
│  └─ 七猫搜索/详情/榜单/下载：纯 Node 实现                 │
└───────────────┬────────────────────────────────────────┘
                │ HTTP 127.0.0.1:18423（仅内网）
                ▼
┌────────────────────────────────────────────────────────┐
│ 内核：Tomato-Novel-Downloader（Rust，独立上游项目）       │
│  ├─ /api/status  /api/search  /api/preview/<id>          │
│  ├─ /api/jobs    /api/library /api/preview-cover/<hash>  │
│  └─ 内容来源：Official-API crate + 闭源第三方 API 池      │
└────────────────────────────────────────────────────────┘
```

### 1. 内核依赖（硬依赖）

- 番茄搜索 / 详情 / 下载的全部数据来源；内核以 `--server --data-dir <dir>` 启动，监听 `127.0.0.1:18423`。
- 内核自身依赖 `tomato-novel-official-api` crate，以及**闭源的第三方正文 API 地址池（地址与 token 未开源）**，
  因此番茄正文抓取最终依赖内核作者的 API 服务。
- 镜像构建时按 `TARGETARCH` 自动下载官方 **Linux 预编译二进制**（amd64 / arm64），无需本地编译。

### 2. 第三方接口依赖（运行时）

| 目标 | 用途 | 方式 |
|---|---|---|
| 内核 REST（本地） | 番茄搜索/详情/下载 | 间接依赖内核 API 池 |
| `fanqienovel.com` | 番茄榜单、改名书页 | HTML 抓取（浏览器 UA + 重试） |
| `api-bc.wtzw.com` / `api-ks.wtzw.com` | 七猫搜索/详情/目录/下载 | 自研签名（MD5）+ AES-128-CBC 解密 |
| `www.qimao.com` / `zuozhe.qimao.com` | 七猫榜单 / 改编书单 | 普通 JSON 接口 |

### 3. 依赖结论

| 问题 | 结论 |
|---|---|
| 是否依赖上游项目？ | **是**：Rust 内核 `Tomato-Novel-Downloader`（其正文来源含闭源 API 池） |
| 是否依赖第三方接口？ | **是**：番茄官网、七猫系列 API |
| 能否容器化部署？ | **可以**：内核提供官方 Linux 二进制；本服务仅用 Node 内置模块，无原生依赖 |

## 二、总体架构

```
        ┌─────────────────────────────────────────────────┐
        │            单容器（node:20-bookworm-slim）        │
        │                                                  │
浏览器 ─┼─:8080─► Node 服务（公开端口）                     │
        │          ├─ /api/rank*    榜单（番茄/七猫）        │
        │          ├─ /api/search   搜索（番茄/七猫）        │
        │          ├─ /api/book     详情                    │
        │          ├─ /api/download 创建下载任务             │
        │          ├─ /api/tasks    任务进度 / 取消          │
        │          ├─ /api/library  文件库 / 删除            │
        │          ├─ /api/file     文件下载                 │
        │          ├─ /api/cover    封面代理                 │
        │          └─ /api/logs     运行日志（预览/下载）    │
        │                 │ 内部 127.0.0.1:18423             │
        │          ┌──────▼───────────────────┐              │
        │          │ 番茄内核（Rust，子进程）   │              │
        │          └──────────────────────────┘              │
        └───────────────┬───────────────┬────────────────────┘
                        │               │
                  /data 卷         /downloads 卷
        （内核配置/日志、库索引、历史、暂存）  （小说成品 TXT，持久化）
```

### 技术选型

- **运行时**：Node.js 内置 `http` / `crypto` / `zlib` / `child_process` / `fs`，**零 npm 运行时依赖** —— 镜像小、构建稳、易审计。
- **前端**：原生 HTML/CSS/JS 单页应用（Hash 路由），无构建步骤。
- **引擎**：内核 Linux 预编译二进制随镜像分发，以子进程方式内部启动，仅监听 `127.0.0.1:18423`。
- **七猫**：签名 / AES 解密 / ZIP 解包 / TXT 写出全部用 Node 实现，不调用任何外部工具。

## 三、关键设计

### 3.1 持久化与「产物不污染」

| 卷 / 变量 | 默认 | 说明 |
|---|---|---|
| `/data` 卷 | `./data` | 内核 `config.yml`/`logs`、库索引、历史、**暂存目录** |
| `/downloads` 卷 | `./downloads` | **小说成品目录**（TXT），宿主机路径可任意指定 |
| `DOWNLOAD_DIR` | `/downloads` | 容器内成品目录 |
| `WEB_PASSWORD` | 空 | 非空则开启访问口令 |

**关键点**：内核的 `save_path` 被指向 **`/data/staging`**，而非 `/downloads`。
原因是内核在**预览阶段就会往 `save_path` 写入 `<book_id>/cover.jpg`**；若直接指向持久化目录，
浏览榜单就会在下载目录里堆出一堆封面文件夹。因此：

1. 内核产物先落 `/data/staging`；
2. 后端在任务完成后把成品 TXT **搬运**到 `/downloads`，并规范命名为 `书名 作者 [ID].txt`；
3. 中间文件（封面、缓存）全部留在 `/data`，`/downloads` 只保留成品。

**运行日志**：封面（主源失败 / 备用源命中 / 全部不可用）、搜索（关键词、结果数、耗时、错误）、
下载（任务创建 / 完成 / 失败 / 取消）与服务启停等事件，追加写入 **`/data/logs/app.log`**
（超过 5MB 轮转为 `app.log.1`），并同时输出到 stdout；设置页可预览与下载，接口为 `/api/logs`、`/api/logs/download`。

### 3.2 内核子进程管理

- 启动前写入/修正 `config.yml`（`save_path`、`novel_format: txt`）；配置损坏或缺键时回退默认模板，避免内核因 `invalid yaml` 起不来。
- 启动后轮询 `/api/status` 健康探测（冷启动最多等 60s）；端口上已有可用内核则直接接管。
- 进程意外退出时**限流自动重启**（最多 3 次，间隔 3s）；服务退出时回收子进程。
- **优雅降级**：内核不可用时，七猫与番茄榜单仍可用，前端顶部给出明确状态提示。

### 3.3 七猫算法（移植要点，**禁改**）

为保证与官方客户端一致，以下常量与流程必须原样保持：

- 签名密钥 `d3dGiJc651gSQ8w1`；签名 = 对 8 个固定头按 key 排序拼接 `k=v` 后追加密钥，取 MD5 小写 hex。
- app-version 从 21 个版本号中按 `stableHash(book_id)` 取模选取；**UA 不参与签名**。
- 正文解密：AES-128-CBC，密钥为 hex `32343263636238323330643730396531` 的 16 字节，
  IV = base64 解码后的前 16 字节，密文为其余部分，**手动去 PKCS7 填充**。
- 下载包为 ZIP，文件名去扩展名即章节 ID；`queryEncode` 须与 Go `url.Values.Encode` 语义一致（空格→`+`，保留 `-_.~`）。

### 3.4 安全

- 封面统一经 `/api/cover` 代理，规避浏览器跨域与混合内容。
- 文件读写做目录穿越校验（基准目录先 `path.resolve` 归一化）与文件名白名单过滤。
- 内核仅监听 `127.0.0.1`，不对外暴露；对外仅暴露 Node 服务端口。

## 五、风险与边界

1. **内核正文来源含闭源 API 池**：上游随时可能变更或失效。缓解：内核版本可配置、可升级；
   使用官方原样二进制，内核自身的热补丁校验可对上。
2. **构建期需联网下载内核**：支持镜像加速前缀（`ghfast.top`）与本地 `KERNEL_BIN` 注入两条路径。
3. **反爬 / 风控**：榜单为网页抓取，沿用浏览器 UA 与重试；被拦截时给出明确中文提示。
4. **功能边界**：不含「短剧 IP 命中」（需浏览器登录态与系统钥匙串）；七猫 EPUB 为可选、默认 TXT。
5. **合规**：见下方使用声明。
